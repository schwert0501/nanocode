# 算子开发联调 · 标准流程

> 当用户提出「开发算子某功能 / 改接口 / 联调 / 修 bug」等需求时，按本流程执行。

## 1. 开工前
- 读懂需求：输入输出、边界条件、异常分支分别是什么？
- 先读相关现有代码，沿用项目已有的风格、工具库与目录约定，不引入新依赖。
- 影响面评估：改动会牵连哪些上下游 / 接口 / 数据？

## 2. 开发
- 小步提交，一次只改一件事。
- 复用已有工具函数，不重复实现。
- 关键路径加必要的错误处理与日志，但不过度防御。
- 涉及外部输入做校验；涉及 SQL 用参数化。

## 3. 自检清单（提测前必过）
- [ ] 本地能编译 / 构建通过？
- [ ] 跑过相关单测？新功能/修 bug 是否补了测试？
- [ ] 正常流程 + 至少一个异常流程都验证过？
- [ ] 没有残留调试代码 / 临时文件 / 硬编码密钥？
- [ ] diff 里没有夹带无关改动？

## 4. 联调 / 交付
- 说明改了什么、怎么测的、哪些场景没覆盖。
- 接口变更要同步给上下游，并更新文档。
- 修 bug 时说明根因，而不仅是「改好了」。
