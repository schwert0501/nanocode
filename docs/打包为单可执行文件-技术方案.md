# nanocode 打包为单可执行文件 — 技术方案（待 review）

> 目标：把整个工程打成一个可迁移的产物，把依赖一起带走，换机器/发给同事即可运行。
> 状态：**方案待决策**，尚未改动任何代码。

## 1. 背景与结论

- 核心运行时**零第三方依赖**：`requirements.txt` 明确只用 Python 标准库（HTTP 走 `urllib`，知识库 BM25 为纯标准库实现）。唯一可选依赖 `numpy`（语义检索后端的 int8 反量化与余弦计算），不装自动回退 BM25，不影响其余功能。
- 入口 `nanocode.py` 仅本地导入 `session / tools / knowledge` 三个包，无外部包引用。
- **结论：可以打成单文件可执行程序。** 但工程多处用 `__file__` 相对定位数据/状态目录，打包（尤其 PyInstaller onefile）后会出问题，需先改两处路径逻辑。

## 2. 方案选型

| 方案 | 产物 | 目标机是否需 Python | 改动量 | 适用场景 |
|---|---|---|---|---|
| **A. PyInstaller onefile** | 单个原生二进制 | 不需要 | 需改 `_BASE_DIR` 冻结判断 + 可写目录外移 | 发给未装 Python 的同事，双击/直接跑 |
| **B. zipapp (.pyz)** | 单个 `.pyz` | 需要 3.8+ | 几乎不用改 | 团队内部换机器，均有 Python |

建议：对"真正可迁移、不依赖系统 Python"的诉求，选 **A**；若只是内部换机，**B** 最省事。下文以 A 为主，B 作为备选。

## 3. 打包前必须处理的 3 个问题

工程中反复出现的定位模式：

```python
_BASE_DIR = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
```

涉及文件：`knowledge/kb.py`、`knowledge/agent_config.py`、`knowledge/skills.py`、`knowledge/gaps.py`、`session/session.py`、`session/changelog.py`。

### 问题 1：只读数据定位（AGENTS.md、.nanocode_skills/、.nanocode_kb/）

PyInstaller onefile 运行时把内容解压到临时目录，`__file__` 指向临时目录（`sys._MEIPASS`），不再是工程所在位置。需区分冻结态：

```python
import sys, os
if getattr(sys, "frozen", False):
    _BASE_DIR = sys._MEIPASS          # 只读资源：PyInstaller 解压目录
else:
    _BASE_DIR = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
```

并用 `--add-data` 把这些只读数据打进包：`AGENTS.md`、`.nanocode_skills`、`.nanocode_kb`、`knowledge/assets`。

### 问题 2：可写状态会丢（sessions / changes / gaps）

`.nanocode_sessions`、`.nanocode_changes`、`.nanocode_gaps` 当前都写在 `_BASE_DIR` 下。onefile 下会写进临时解压目录，**进程退出即被清除**，历史会话、改动记录、知识缺口全部丢失。

这些可写路径必须与只读 `_BASE_DIR` 分离，改到持久位置（当前工作目录或用户目录）：

```python
_STATE_DIR = os.getcwd()                       # 方案一：跟随运行目录
# _STATE_DIR = os.path.expanduser("~/.nanocode")  # 方案二：统一到用户目录
SESSIONS_DIR = os.path.join(_STATE_DIR, ".nanocode_sessions")
CHANGES_DIR  = os.path.join(_STATE_DIR, ".nanocode_changes")
GAPS_DIR     = os.path.join(_STATE_DIR, ".nanocode_gaps")
```

> 决策点：状态放「运行目录」还是「用户目录」，需 review 时拍板。运行目录更贴近"项目隔离"，用户目录更适合"全局单实例"。

### 问题 3：readline（macOS libedit 兼容）

`nanocode.py` 已对 libedit / GNU readline 做了双份绑定与降级处理。PyInstaller 一般能带上该模块，但打完需**实测**：Tab 命令补全、Shift+Tab 切换权限模式、多行粘贴（bracketed paste）是否正常。

## 4. API / 环境配置（迁移友好，无需改）

密钥与模型全部走环境变量，不进包：

- `OPENROUTER_API_KEY` / `ANTHROPIC_API_KEY`（二选一）
- `API_URL`（默认 `https://oneapi-comate.baidu-int.com/v1/messages`）
- `MODEL`（默认 `Opus 4.8`）
- 可选：`GAP_UPLOAD_URL` / `GAP_UPLOAD_AUTH`（知识缺口上传）

运行前 `export` 即可，这部分对迁移天然友好。

## 5. 打包步骤（方案 A）

```bash
pip install pyinstaller
cd nanocode-master

pyinstaller --onefile \
  --name nanocode \
  --add-data "AGENTS.md:." \
  --add-data ".nanocode_skills:.nanocode_skills" \
  --add-data ".nanocode_kb:.nanocode_kb" \
  --add-data "knowledge/assets:knowledge/assets" \
  nanocode.py
# 产物：dist/nanocode
```

注意：
- macOS/Linux 用 `:` 分隔 `--add-data`，Windows 用 `;`。
- 当前工程**没有** `.nanocode_kb` 目录，需先 `/kb index` 建好索引再打；否则去掉该行 `--add-data`。
- 若需语义检索后端，还要把 `knowledge/assets/`（约 14MB 静态词向量资产）用 `--add-data` 一起打进去，并确保目标环境有 `numpy`；不打则 `vector`/`hybrid` 自动回退 BM25。

## 6. 备选方案 B（zipapp）

```bash
python3 -m zipapp nanocode-master -m "nanocode:main" -o nanocode.pyz -p "/usr/bin/env python3"
# 运行：./nanocode.pyz
```

`.pyz` 内 `__file__` 行为与源码基本一致，问题 1/2 大多不触发；但目标机必须有 Python 3.8+，且只读/可写数据同样建议确认路径。
